# 实施计划与验收

本文保留完整里程碑和验收目标。v0.1.0 已实现 Tauri 桌面工程、只读配额查询、主题和 IPC，当前交付与验证以 [第一版实现说明](IMPLEMENTATION.md) 为准；外部 HTTP / SSE 和后台自动化仍待实现。

## 1. 开发顺序

| 阶段 | 交付物 | 完成条件 |
| --- | --- | --- |
| M0：兼容验证 | 固定上游基线；明文与加密的合成 fixture；账号类型检测；许可决策记录 | 只读解析成功，坏格式明确失败，所有源文件零写回；明确独立实现/获许可复用路线 |
| M1：配额核心 | Rust 领域模型、标准 OAuth provider、调度与内存快照 | mock HTTP 与领域边界用例通过，不使用真实凭据跑自动测试 |
| M2：桌面闭环 | Tauri 2 工程、React HUD、托盘、设置、公开 IPC / SDK | 多账号选择→刷新→展示→推荐完整闭环，权限与错误状态正确 |
| M3：主题扩展 | Schema 校验、导入/预览/应用/回退、三个布局 | 用户可修改示例并导入；未知/错误/过期状态可见且不可移除 |
| M4：外部接口 | 可选 HTTP / SSE、独立 token 与 scopes、SDK 示例 | 外部本机工具可读取、刷新、订阅；未授权/越权/浏览器来源被拒绝 |
| M5：V1 发布 | Windows 安装与便携包、支持矩阵、诊断与升级说明 | 下列发布验收通过；无尚未解决的凭据泄露或写回问题 |

M0–M3 可组成内部预览版；M4 完成后才宣称 V1 提供外部程序接入。M0 若发现未知实际格式，不用关闭加密来绕过；先补适配与合成验证，UI 可先用虚构数据推进。

## 2. 功能与异常验收

- **领域**：执行 [DOMAIN](DOMAIN.md) 的用例，覆盖多个窗口同时耗尽、多个账号、缺字段、无限、不适用、附加功能、排序平局、reset 到点、时间跳变。
- **读取**：明文、加密 v1、缺 key、坏 nonce/认证标签、未知版本、锁定和半写入文件、索引详情不同步、目录联接、路径穿越、源切换、删除账号。
- **请求**：使用 mock server 测试请求 method / headers / 目标控制、成功响应、缺字段、无效百分比、401 token 不变与变化、403、429 两种 Retry-After、超时、超大 body、重定向拒绝。
- **调度**：手动与自动重合不重复发请求、单账号串行/全局并发 2、部分成功、排队超时、旧 generation 结果丢弃、休眠后合并、退避不被手动按钮绕过。
- **数据最小化**：在合成 token/key/邮箱上设置哨兵值，断言公开 JSON、事件、错误、日志、主题文件、配置不出现机密哨兵；短名/用户别名属于明确允许展示的字段。
- **IPC**：HUD 无法调用 settings-only 命令；不允许未声明自定义 command、远程 origin、通用文件读取或网络调用。
- **HTTP**：所有端点鉴权、scope、token 撤销/过期、Host/Origin、限速、只绑定 loopback、作业所有权、幂等键、队列上限、SSE 重连与 resync。
- **主题**：成功 Schema 与语义校验、坏主题拒绝、预览退出、重复 ID 替换、写入失败、启动 fallback、高 DPI、键盘、颜色对比度。

测试重点是跨边界行为与失败恢复，不为纯文案或简单样式编写重复实现的测试。真实账号联调不在默认 CI 中，也不保存认证抓包或将真实账户目录复制进测试数据。

## 3. 界面与 Windows 验收

首次使用只引导选择 Cockpit 数据源与显示账号，不出现登录表单。未选择、源不可读、加密不支持、认证过期、离线、限流、刷新中、数据过期分别有准确文案。错误不得把剩余量变为 100%。

HUD 显示全部选中账号，默认紧凑；长名称和较多窗口有详情入口；刷新按钮显示任务状态，推荐附最后可靠采样依据。托盘在 HUD 隐藏或鼠标穿透时仍可恢复。默认短名，支持本地别名和隐私模式。

验证 Windows 10/11、100%/125%/150%/200% DPI、单双显示器、拔出副屏、休眠唤醒、无 WebView2 Runtime、设置损坏、应用目录只读以及标准用户安装运行。便携包仅表示免安装分发，V1 仍使用当前用户的应用数据目录；随包携带 data 目录是后续独立能力。

首次真实联调应确认本机 Cockpit 版本/格式与支持矩阵一致，仅查询用户选中的账号，不改其设置。上游进程关闭但凭据有效时可刷新；凭据过期时停止肯定推荐；Cockpit 更新凭据后 HUD 能恢复。

## 4. 性能目标（待测，非已达成承诺）

在记录清楚配置的 Windows 11 x64、4 核以上 CPU、8 GiB 内存、SSD 环境测量发布构建：

| 指标 | 初始目标 / 测量范围 |
| --- | --- |
| 启动到首个可交互 HUD | 热启动 ≤2 秒；不把网络等待算进界面启动 |
| 空闲 CPU | 5 分钟平均 <1%，设置关闭、2 个账号 |
| 内存 | 总进程树私有工作集目标 ≤150 MiB，包含 WebView2；记录峰值和波动 |
| 刷新交互 | 请求提交到本地任务提示 <100ms，HTTP 完成受服务端影响 |
| 常驻请求数 | 默认每账号约 5 分钟一次；倒计时不触发请求 |

用 2/10/50/100 个合成账号验证排队和 UI；100 账号是选择上限而非承诺短时全刷新，60 秒队列预算可能使慢任务部分失败，必须反馈清楚。达不到指标时先定位进程、渲染或轮询来源，再决定是否调整目标，不能仅测 Rust 主进程宣称低内存。

## 5. 发布与后续扩展

发布前确定本项目许可证和所引入代码的许可清单；固定依赖版本、确认安装包与 WebView2 行为、记录支持的 Cockpit 格式。源码/协议同步遵循 [UPSTREAM](UPSTREAM.md)，CI 只提出候选变化，应用端不执行上游新源码。

V1.1 可增低额度通知（阈值、冷却、勿扰）、脱敏本地历史（保留期/清除/关闭）、更多只读 provider、更丰富的宿主布局。用户脚本、云端同步、多平台账号管理与模型代理不作为这些扩展的隐含部分。
