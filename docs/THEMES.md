# 主题扩展设计

v0.1.0 已实现主题导入、校验、合成数据预览、切换和回退。本文是 V1 扩展契约；当前范围见 [当前实现](IMPLEMENTATION.md)。运行环境为 Tauri 2，主题渲染由随应用编译的前端负责。

v0.1.1 默认主题为奶油薄荷。为遵守 HUD 的紧凑约束，当前固定使用紧凑行和底部推荐；下文卡片、横排、区域重排和进度条属于保留的扩展设计，当前不渲染。主题颜色、字体、间距继续可配置。装饰性强调色允许使用浅薄荷色；正文和强调色上的文字仍需满足 4.5:1，控件边界和焦点使用高对比度的边框/正文色。

## 1. 使用自己的主题

V1 主题是一个 UTF-8 `theme.json` 文件。可直接修改 [自定义主题模板](../public/theme-template.json) 并导入，字段以 [theme.schema.json](../schemas/theme.schema.json) 为准。复制 [midnight 示例](../examples/themes/midnight/theme.json) 时必须改为新的 `id`，内置 ID 禁止覆盖。

设置页流程：

1. 在“外观 → 导入主题”中选择本地 JSON，限制为 64 KiB；V1 不接收 ZIP、文件夹或网络地址。
2. Rust 读取文件，拒绝重复键、无效 UTF-8、深度超过 16 层的 JSON、未知字段及不兼容版本，再执行 Schema 和语义校验。
3. 用虚构账号预览正常、额度耗尽、认证过期、错误、未知、数据过期、长名称与多配额窗口状态，不读取真实凭据。
4. 用户点击“应用”后，Rust 将验证后的主题复制到本应用数据目录并切换活动主题；关闭预览会恢复原主题。
5. 可随时恢复内置默认主题。导入文件损坏或版本不兼容时保留当前主题；启动时活动主题失效则回退到默认主题，并在设置页说明原因。

解析、校验、预览都必须成功后才能保存。新主题通过同目录临时文件和原子替换写入；活动配置最后提交。替换过程失败保留之前可用的主题，不先删除目标文件。相同 `id` 的导入先展示差异并让用户明确选择替换，避免覆盖时不知情。

主题副本、活动主题 ID 和应用设置只保存在 HUD 自己的数据目录。Rust 按 `id` 生成内部文件名，不使用主题字符串拼接任意路径；不修改导入源文件或 Cockpit 目录。V1 便携包仍使用当前用户的应用数据目录；随包携带独立 `data/` 是后续能力。

## 2. 文件契约与版本

必填字段为 `schemaVersion`、`minHudVersion`、`id`、`name`、`tokens`、`layout`。`author` 和 `description` 可选，只显示为普通文本。

| 字段 | 规则 |
| --- | --- |
| `schemaVersion` | 固定为 `1`；应用不猜测未知版本的含义 |
| `minHudVersion` | `major.minor.patch` 三段非负整数，不含前导零、预发布或构建后缀；运行时按数字比较，要求宿主版本不低于它 |
| `id` | 1–64 个小写字母、数字或连字符，首字符为字母；内置主题使用宿主保留 ID，导入时拒绝占用 |
| `name` | 1–80 个字符，宿主以文本显示 |
| `tokens` | 颜色、系统字体、字号、行高、间距、圆角；数值均有范围 |
| `layout` | 预设布局、密度、配额表现方式、宿主允许的区域与槽位顺序 |

`minHudVersion` 不替代 `schemaVersion`：前者限制应用最低版本，后者控制文件格式兼容。示例中的 `0.1.0` 是首个支持该格式的版本。运行时版本包含预发布标记时，按 SemVer 比较，不能把 `0.1.0-beta` 当作满足 `0.1.0`。V1 发布后的必填字段和既有枚举含义保持稳定；新增可选能力需要相应最低宿主版本，破坏性变更提升 Schema 主版本。

Schema 使用 JSON Schema draft 2020-12，并在每层对象禁止未知属性。JSON Schema 无法独立完成版本比较、文字对比度或布局校验，这些检查必须由宿主执行。

## 3. 布局与数据职责

| 预设 | 场景 |
| --- | --- |
| `compact-rows` | 每个账号一行，适合常驻小窗口 |
| `cards` | 每个账号一卡，适合较多详细信息 |
| `horizontal` | 账号横向排列，适合屏幕边缘 |

`regionOrder` 仅能调整账号区和推荐区的顺序；两区都必须出现一次。`accountSlots` 仅能调整账号名称、配额窗口组和可用性的位置；三个槽位都必须出现一次。`quotaVisualization` 可选纯文字或进度条加文字，均保留具体数值及文本状态。

宿主把统一数据模型映射到这些槽位：账号使用脱敏显示名称；配额窗口通过数组呈现 `label`、剩余值、重置时间及状态。主题不假定一定存在“5h / 7d”，不解释接口原始字段，不排序推荐账号，也不计算倒计时、可用性或推荐结果。窗口数组为空或结构未知时由宿主展示明确的未知状态，不能推断为满额。

刷新、设置和窗口控制由宿主提供，不属于可移除槽位；每个账号的状态和更新时间也由宿主保留。`unknown`、`error`、`stale`、认证过期、刷新中和部分查询失败必须在所有布局中可见。旧数据允许保留，但同时显示数据过期或失败提示以及最后成功更新时间。配额窗口过多时使用宿主滚动或详情展开，并提示仍有更多窗口，不截断后假装完整。

主题不能控制数据读取、网络请求、刷新频率、推荐规则、日志内容、隐藏账号、窗口穿透或应用权限。账号选择、置顶、隐私遮罩等属于独立应用设置。

## 4. 样式与可访问性

- 颜色只接受不含透明通道的 `#RRGGBB`。字体只接受 `system` / `system-monospace`，由宿主映射到系统字体栈；不导入字体或远程资源。
- 文字必须满足相对其实际背景至少 4.5:1 的对比度；必要的状态图形、控件边界和焦点指示至少 3:1。运行时检查实际配对：正文、弱化文字、状态文字相对于各使用背景，以及强调文字相对于强调背景。失败时拒绝应用，并指出需修改的 token；这不是 Schema 的能力。
- 状态必须同时具备文字或图标说明，不能仅凭颜色区分。进度条保留文字数值；未知值不用 `0%` 或 `100%` 占位。
- 字号范围为 12–20，行高为 1.2–1.8；宿主缩放和高 DPI 设置优先。长账号名称可省略，但必须有可访问完整名称和键盘可达的详情。
- 刷新、设置与关闭等交互控件保留清楚的焦点指示及至少 32 × 32 逻辑像素点击区域；紧凑布局不能覆盖这些约束。宿主高对比度模式可覆盖主题颜色。
- V1 不支持自定义动画。遵循系统减少动态效果设置；鼠标悬浮详情也必须支持键盘与点击。

## 5. 与开放接口的关系

主题是声明式数据，不是插件程序。V1 不执行 JavaScript、CSS、HTML、表达式或模板，不读取外部图片、字体及任意文件，不提供第三方运行时脚本入口。

Tauri IPC 和类型化 SDK 面向随应用构建、经过审核的前端模块及自行编译的自定义前端，提供读取快照、请求刷新、监听变化、读取设置等能力。主题只接收宿主整理后的显示数据，不直接调用 IPC，也不能获得 access token、refresh token 或原始账号文件。若以后需要第三方可执行扩展，应另行设计权限、隔离和签名机制，不能把它混入主题 V1。

## 6. 实现验收清单

- 示例通过 Schema；缺字段、额外字段、非法颜色、越界数字、重复或缺失槽位均被拒绝。
- 导入拒绝未来 Schema、过高最低版本、保留 ID、超限文件及路径伪装；文件选择由宿主完成。
- 全部预设通过虚构数据预览，覆盖无账号、正常、耗尽、认证过期、未知、错误、过期、多窗口和长名称。
- 校验文字及控件对比度，键盘操作、高 DPI、系统高对比度与减少动态效果均可用。
- 保存中断、启动损坏、删除活动主题时可回退；真实账号数据和凭据不会进入主题文件或预览数据。

### 0.1.2 HUD 统一显示规则

三个内置主题均使用紧凑间距、无悬停详情、avaliable 底栏和设置/刷新全部/隐藏图标。额度颜色由固定 20/50/80 阈值计算，明暗色值根据主题背景调整。重置次数仅在接口提供有效数字时显示，主题不得推算。旧 spacing 和 showHoverDetails 字段保留兼容，当前 HUD 使用统一紧凑间距并关闭悬停详情。
